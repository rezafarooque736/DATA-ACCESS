## 2) Your current totals query is fine

Use this for the main customer-wise status table:

```sql
SELECT
  customer,
  SUM(CASE WHEN act = 'blocked' THEN 1 ELSE 0 END) AS blocked,
  SUM(CASE WHEN act = 'passed' THEN 1 ELSE 0 END) AS passed,
  SUM(CASE WHEN act = 'alarmed' THEN 1 ELSE 0 END) AS alerted,
  COUNT(*) AS total
FROM "syslog"
GROUP BY customer
ORDER BY total DESC;
```

This is the correct replacement for your current `COUNT(*) AS total` plus `SUM(CASE...)` query.

## 3) Production pattern for averages

Do **not** calculate averages from the selected dashboard range with `COUNT(*) / 15` or `AVG(action)`. That will never give the metrics you want.

Instead, use `histogram()` to bucket the time range, then take the average of the bucket counts. OpenObserve documents `histogram()` specifically for fixed time buckets and time-series analysis. ([openobserve.ai][2])

### A. Average over the selected panel range, per minute

Use this for the panel whose time range is whatever the user selected in the dashboard:

```sql
SELECT
  customer,
  ROUND(AVG(bucket_count), 2) AS avg_per_min
FROM (
  SELECT
    histogram(_timestamp, '1 minute') AS bucket,
    customer,
    COUNT(*) AS bucket_count
  FROM "syslog"
  GROUP BY bucket, customer
) t
GROUP BY customer
ORDER BY avg_per_min DESC;
```

If the selected range is 15 minutes, this gives the 15-minute average per minute.
If the selected range is 1 hour, it gives the 1-hour average per minute.

## 4) How to build the dashboard correctly

OpenObserve supports SQL-based table panels with multiple queries, but the **time window is panel-scoped**, so the production setup is to use **one dashboard tab with multiple panels**, not force six different windows into a single time scope. OpenObserve also supports auto-refresh and panel-level time configuration. ([openobserve.ai][1])

So the dashboard layout should be:

* Panel 1: **Current selected range totals**
* Panel 2: **Last 1 hour avg/min**
* Panel 3: **Last 24 hours avg/hour**
* Panel 4: **Last 7 days avg/day**
* Panel 5: **This week avg/day**
* Panel 6: **Previous week avg/day**

That gives you exactly what you asked for, without breaking OpenObserve’s time model.
